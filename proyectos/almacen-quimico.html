Caso de estudio · Rediseño UX/UI

Almacén Químico

Rediseño del sistema con el que alumnos y almacenistas de la FCQI piden, entregan y reciben material de laboratorio. El sistema funcionaba, pero nadie sabía bien qué hacer en él.

Rol
Diseño UX/UI de todas las vistas · apoyo en CSS
Contexto
Servicio profesional para el Almacén de Química, FCQI · UABC
Usuarios
Alumnos · almacenistas · administrador
Herramientas
Figma · Design System · Django + Bootstrap
01

El problema

El sistema ya estaba programado y hacía su trabajo, pero se veía y se sentía como un borrador: vistas grises, listas planas y acciones importantes escondidas entre otras.

  • El menú lateral solo tenía íconos sin texto.
  • "Entregar" y "Rechazar" tenían el mismo peso visual, aunque una es irreversible.
  • El almacenista veía matrículas en vez de nombres y ningún resumen del día.
  • El inventario solo se actualizaba en Excel al final del semestre.
¿Cómo hacer que pedir y entregar material sea claro para el alumno y rápido para quien atiende el almacén?
02

Cómo lo abordé

Antes de dibujar una sola pantalla, recorrí el sistema completo y lo documenté.

  1. Auditoría de vistas

    Mapeé cada pantalla, botón y a dónde lleva, para los tres roles. Así encontré 16 vistas con problemas y las prioricé.

  2. Visita al almacén

    Entrevisté a la encargada del almacén. De ahí salieron necesidades que el sistema ni contemplaba, como un inicio con el resumen del día.

  3. Referentes

    Analicé dashboards de inventario para entender cómo otros resuelven listas densas y estados.

  4. Design System → Figma

    Definí colores, botones y badges primero, y después diseñé todas las vistas de alumno, almacenista y administrador.

03

Design System

Usé la identidad de la UABC con una regla 60 / 30 / 10: base neutra cálida, verde institucional para acciones positivas y arena dorada para la acción principal. Cada estado de una solicitud tiene su color y su ícono, para que se reconozca de un vistazo.

60% neutro 30% verde 10%
04

Antes y después

Arrastra la línea para comparar el sistema original con el rediseño.

05

Lo que no existía

La visita al almacén reveló necesidades que el sistema no cubría. Diseñé vistas nuevas para ellas:

  • Inicio del almacenista con el resumen del día: solicitudes pendientes, entregas, devoluciones vencidas y adeudos.
  • Reportes filtrables por estado y fecha, exportables a PDF, XLS o HTML.
  • Escáner QR con búsqueda manual y los escaneos recientes a la vista.
06

Pedir material, paso a paso

El flujo más usado por los alumnos. Lo dividí en pasos cortos, con confirmación al final para que nadie se quede con la duda de si su solicitud se envió.

07

Iterar con la encargada

Presenté avances a la encargada del almacén y sus comentarios cambiaron el diseño en puntos que no había contemplado:

Apartar material

Si una solicitud no se recoge, el material vuelve al stock. Agregué un aviso con el tiempo límite para recogerlo.

Préstamos de varios días

Algunos materiales se devuelven otro día. Añadí un mini calendario para elegir la fecha de devolución.

Pagar o reemplazar

Un adeudo puede saldarse mezclando pagos y reemplazos. El almacenista elige qué artículos se pagan y cuáles se reponen.

Hoy: el equipo de desarrollo está implementando el rediseño sobre el sistema en Django, y yo apoyo con el CSS para que el resultado sea fiel al diseño.
